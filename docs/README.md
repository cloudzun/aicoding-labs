## 二、两条轴怎么配合用

```
写需求/定指标    → 轴二（口径、基线、现实性判定）
写规格/排流程    → 轴一（八环、门禁、产物契约）
写评测          → 轴二（指标定义 + 统计）+ 轴一（证据纪律）
做评审          → 轴一（DoD/反模式/独立复核）
对客汇报        → 轴二（演示脚本 + 指标呈现 + 边界声明）
```

一句话：**轴一管"怎么做得可信"，轴二管"做得对不对、够不够、客户认不认"。**

## 三、六条最重要的结论（先记住这六条）

1. **门禁只有两处是硬数字**：spec ≥7 分、ship 覆盖率 60%/80%。其余打分不阻断，别把打分记录当门禁讲。
2. **未验证 ≠ 已验证为否**：`unavailable`／`null`／`not_assessed`／`UNVERIFIED` 四种状态必须有表达位。
3. **AI 项目的证据承重墙要换**：不是"测试全绿"，而是"固定评测集 + 多次运行 + 版本三元组（模型/提示词/评测集）"。
4. **客户的 3 秒和 2 秒原口径不成立**：按 MLPerf 交互档反推，3 秒只够约 50 个汉字。必须改成 TTFT + 流式。
5. **5 个百分点的判定需要 n ≥ 200**：n=50 时置信区间 ±8.3pp，测了等于没测。
6. **演示的胜负在"主动演示失败"那 4 分钟**：MIT 调研 95% 试点失败的根因是"不适配工作流"，happy path 恰好掩盖它。

## 四、维护约定

- **置信度标注**：✅ 已核实原文 ｜ 🔧 工程推断 ｜ ⚠️ 未核实/厂商自测。新增内容必须带标注。
- **不编数字**：没有来源的数字一律不写；写不出就写"未找到"。
- **回填机制**：主文档里标〔推断〕的部分（轴一第 8–9 节、轴二第 10 节时间盒），demo 实跑后必须按实际结果回填，不得沿用推断。

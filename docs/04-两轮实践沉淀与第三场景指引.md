## 二、新增 8 条最佳实践（两轮共有）

### BP-1 一次输入量有上限，超了就"静默失声"

**证据：** ② 把 3–6 万字符一次性送审，deepseek/sol 返回 **HTTP 200 + 空 content**；实测 deepseek/sol 在 >~1.5k 字符即空，glm/kimi 在 ~5k 不稳。① 的 judge 截断（42% 失败）是同一类。

**做法：** 任何"长材料交给模型"的动作，都要 ① 分片、② 多模型回退、③ **对空响应显式断言**（不能把空当"没意见"）。

### BP-2 尺子必须先被量（测量工具自检）

**证据：** ① judge 配置错误 → 42% 判定静默失败；② 比对器 5 处失真 → EX 低 4pp。两次都是"自测全绿但结论错"。

**做法：** 环 0 增加两项固定产出——
- judge 自检集：10 条人工已知答案，必须 10/10；
- 比对器单测：5 组构造样本（多一列/少一行/顺序不同/浮点抖动/NULL vs "None"），必须全对。

### BP-3 题库不变量（出题也是一门工程）

**证据：** ② 四类不公平：gold 带题面未要求的 LIMIT、gold 列多于题面、模板自带 ORDER BY、题面没说"前 N 条"。

**做法：** 把不变量写成断言，随题库一起跑：
1. 有 `LIMIT` 必须有 `ORDER BY`；
2. 题面必须覆盖 SQL 每一输出列；
3. 排序要求必须显式出现在题面；
4. 配额断言（少一题就报错）。

### BP-4 闸门分级：不是所有"不确定"都要拦

**证据：** ② 歧义分 blocking（营收/近三月）与 advisory（在网/月费/SLA），advisory 率 17.33%。

**做法：** 每个闸先问两句：**有没有默认口径？** 有 → 提示后作答；没有 → 拦。拦错的代价是可用性，放过的代价是错误答案——按场景选。

### BP-5 写操作要"显式拒绝"，而不是"静默改写"

**证据：** ② 实测"帮我删掉账单"被模型解释成查询并正常返回数据，用户会以为已删除。

**做法：** 意图闸（动词识别）先于生成；拒绝文案要说明"只读 + 怎么改成查询"。**安全上不算漏洞，体验上是事故。**

### BP-6 授权器优于黑名单

**证据：** ② 第一版 authorizer 末尾"其它放行" + 函数黑名单；codex 指出 ATTACH/未列函数可绕过。改**默认拒绝 + 白名单**后 12/12 仍过。

**做法：** 安全判定一律"白名单 + 默认拒"，只在明确列出能力时放行。

### BP-7 评测要能进 CI（退出码 + 不得用子集判 PASS）

**证据：** ② 第一版 `run_eval` 无论 FAIL 都 `return 0`，且 `--limit` 子集也能 PASS → 假绿。

**做法：** PASS→0、FAIL→2、INCOMPLETE→3；子集模式只冒烟不打验收结论；延迟等指标要真的进门禁，不能只写在报告里。

### BP-8 独立评审要"可执行"

**证据：** ② 两轮评审：glm（分片）找出 16 条，codex（沙箱自主读文件）找出 19 条，其中 5 条直接改变结论。

**做法：** 评审要求写死：清单化、逐条给文件:行号与触发条件、只报真问题、可分片。**评审最大的价值不是找 bug，而是抓"结论可能是错的"。**

## 三、反模式清单（两轮踩过的坑）

| 反模式 | 后果 | 替代做法 |
|---|---|---|
| 用展示层数据做评测 | ② 大结果集必错，压低 4pp | 评测用全量，展示单独截断 |
| 让被测模型自己判对错 | ① judge 单点失效即全线失真 | 换家族 + 锚点校准 |
| 用整篇文档当标准答案 | ① 口径过严，正确也被判半对 | 最小事实点/要素集合 |
| 只给文字规则不给示例 | ② JOIN 规则写了但模型不遵守 | few-shot 示例 + 确定性改写闸 |
| 一次性大 prompt 求稳 | 长输入空响应 | 分片 + 回退 + 非空断言 |
| 评测集配额靠"差不多" | 桶不足导致结论无意义 | 配额断言随题库跑 |
| 把"未达标"藏进 notes | 交付不可信 | 写进 Known issues，门禁如实 FAIL |

## 四、对第三个场景（合同审查）的直接指引

| 经验 | 在合同审查里怎么用 |
|---|---|
| BP-2 尺子自检 | ③ 必然要用 LLM 判语义规则 → **先建 judge 自检集**（10 条人工已知），否则重蹈 ① |
| BP-3 题库不变量 | ③ 的"缺失项"题必须写明"应有哪些条款"，否则无法判定 |
| BP-1 分片 | 合同 10–30 页必须分片抽取，**不能整份塞入** |
| BP-4 分级闸 | 数值类规则交代码（硬）；语义模糊类给"建议+置信度"（软） |
| BP-6 白名单 | ③ 的规则引擎应有"规则白名单"，禁止 LLM 自创规则 |
| BP-7 CI | ③ 的召回/精确必须成对进门禁，单报召回等于奖励乱报 |
| BP-8 评审 | ③ 建议同时找"法务视角"的人工评审（不只是模型评审） |

## 五、一句话

**两轮下来最硬的一条经验是：AI 项目里"测量"和"能力"要用同样的工程强度对待。** ①② 各有一半的问题不在模型，而在尺子、题库和闸门——这三样恰好是**可以完全掌控**的部分。

# 改进建议台账与"是否过关"判定

> 回答两个问题：① 三案例作为**教学案例**质量是否过关？② 剩下的改进（③ 长文分块/judge 自检集、② JOIN 专项）该做还是只记录？
> 原则：**教学过关 ≠ 交付过关**。两者判据不同，不能互相替代。

---

## 一、判定标准（6 条，先立标准再看结论）

| # | 标准 | 为什么它是标准 |
|---|---|---|
| S1 | **八环完整且有产物** | 教学讲的是流程，没有产物就没有可讲的证据 |
| S2 | **有真实失败可讲** | 全绿的案例讲不出"门禁为什么存在" |
| S3 | **指标可复现** | 学员照着跑能得同样结果，否则只是听说 |
| S4 | **记录可复盘** | 决策/口径/证据可追溯，否则无法讨论"为什么这样选" |
| S5 | **有验证手册** | 学员/客户能自己验证，不依赖讲师 |
| S6 | **三案例形成方法递进** | 课程主线是"举一反三"，不是三个孤立 demo |

## 三、把"剩余建议"分成三类（这是回答"该不该做"的关键）

| 类 | 定义 | 例子 | 处置 |
|---|---|---|---|
| **A 教学材料缺口** | 缺了学员看不懂/讲不通 | ② 缺会审记录、①② 缺证据索引、③ 缺诊断专章、AC 条数错 | **必须做**（**已完成**） |
| **B 机制性短板** | 不影响讲课，但影响真实可用性与结论可信 | ③ judge 自检集、③ 长文分块、② JOIN 专项 | **记录 + 设触发条件**，不现在做 |
| **C 指标打磨** | 只为把数字做上去 | ② 补 tiebreaker、① 调 prompt 再冲覆盖率 | **只记录** |

**判断依据：**
- 教学场景的核心问题是"**能不能讲清一个完整性过程**"，A 类直接影响，B/C 不直接。
- B 类反而有教学价值：③ 的"没有 judge 自检集 → 语义翻车"本身就是 BP-2 的活案例，**做完了这个案例就没了**。
- C 类做了只会让"真实失败"变少，教学收益为负。

## 五、我的建议（三句话）

1. **教学层面：停止打磨，进入课程化。** 六条标准全过，再改指标对讲课没有增量；下一步应是把材料转成教案/PPT/练习/考核题。
2. **交付层面：保留缺口，写进方案风险章节。** 三案例的"未达标"是真实信息，比一个漂亮的 90% 更有商业价值——它能支撑"需要多少工时/什么环境"的报价。
3. **只在一种情况下动手：** 客户明确要求某一项（如"必须看语义层可信"→做 IMP-01，40 分钟）。否则一律按台账记录，不主动改。

**做 IMP-01（③ judge 自检集，40 分钟）。**

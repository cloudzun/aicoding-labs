## 1. 主链路：问 500 万（约 2 分钟）

**输入（逐字复制，Enter 发送）**

```text
单笔采购金额500万元以上的采购项目，需要提交什么会议审议？
```

**你会看到**

- 答案（原文）：

  > 结论：单笔采购金额500万元以上的采购项目，其采购方式、采购文件和采购结果应提交总经理办公会审议。[c01] 依据：该权限规定自2025年3月1日起施行；此前《采购管理办法》第十二条的采购审批权限规定已于同日废止，因此应按现行细则执行。[c08]

- 两个蓝色角标 `[c01]` `[c08]`，可点击
- meta 行：`2.77s ｜ opencode-go/gpt-6-luna ｜ ttft 1419ms ｜ trace t8e07c58361e344f2`（界面计时 2.77s；服务端自报 `elapsed_ms=2749`，两者差在浏览器往返）
- 右侧 **8 条**来源卡，每条含：《文档名》+ 条款号 + 生效日期 + 状态 + `示例文本` + `score`

**右侧 8 条来源（实测）**

| 序号 | 文档 · 条款 | 生效 | score |
|---|---|---|---|
| c01 | 采购审批权限实施细则 · 第十条 | 2025-03-01 | 0.9999 |
| c02 | 采购审批权限实施细则 · 第七条 | 2025-03-01 | 0.9997 |
| c03 | 采购管理办法 · 第十二条（**旧口径**） | 2023-04-01 | 0.9994 |
| c04 | 采购审批权限实施细则 · 第十三条 | 2025-03-01 | 0.9993 |
| c05 | 全面预算管理办法 · 第二十条 | 2024-03-15 | 0.9916 |
| c06 | 采购管理办法 · 第二十六条 | 2023-04-01 | 0.0 |
| c08 | 采购审批权限实施细则 · 第二十六条（**附则/废止条款**） | 2025-03-01 | 0.0 |
| c10 | 全面预算管理办法 · 第二十四条 | 2024-03-15 | 0.0 |

**要看的三件事（本案例的核心卖点）**

| 来源 | 原文要点 | 用途 |
|---|---|---|
| c01 | 500 万以上→总经理办公会；200–500 万→分管副总；50–200 万→采购与供应链部负责人；50 万以下→需求部门负责人 | 现行口径 |
| c03 | 300 万以上→总经理办公会（**旧版**） | 旧条文也在上下文里，会干扰 |
| c08 | "《采购管理办法》第十二条关于采购审批权限的规定同时废止" | 模型靠这条否掉 c03 |

**讲点：** "召回 100% 不代表可信"——新旧条文同时在上下文里，模型必须自己做时效判断；这一点是案例一区别于普通问答的关键。

**注意：** score 显示 0.0 不等于被丢弃（c08 的 score 是 0.0，却被引用了）。**不要用单条 score 当相关性判据。**

## 2. 点引用核对（1 分钟）

**操作：** 点答案里的 `[c01]` → 右侧对应卡片高亮并平滑滚动；再点 `[c08]`。

**你会看到：** 卡片 `c01` 高亮，正文即"第十条 单笔采购金额在500万元以上的采购项目…"；`c08` 高亮后能看到附则原文。

**讲点：** 答案可点回原文段落 = 可核查。现场被问"你怎么证明不是编的"时，点两下就够。

## 3. 多轮追问（1 分钟）

**输入（同一个会话接着问）**

```text
那需要几个人签字？
```

**你会看到**

- meta 行出现 `拒答` 标签
- 答案（原文）：

  > 资料不足。材料只说明单笔采购金额500万元以上的采购项目，其采购方式、采购文件和采购结果应提交总经理办公会审议，并未说明需要几个人签字。[c01] 请咨询采购与供应链部或相关审批部门确认签字要求。

- 耗时 **2.40s**，ttft 1315ms，仍是 8 条来源

**讲点：** 这是"部分可答 + 明确缺口"——它没有编一个签字人数，也没有整段摆烂，而是把"已知的"和"材料没写的"分开说。比"全拒"更难，也更像真实业务助手。

## 4. 失败演示：拒答（1.5 分钟，必演，不要删）

**输入**

```text
员工的婚假有多少天？
```

**你会看到**

- 答案（原文）：

  > 资料不足：制度库中没有找到与「员工的婚假有多少天？」直接相关的规定，我不能给出确切结论。 建议：请向制度归口部门确认；或提供相关文件后再检索一次。

- 右侧仍列 **5 条**来源，但 score 极低：`0.0009 / 0.0004 / 0.0003 / 0.0002 / 0.0002`
- meta 行显示 `ttft -ms`（**没有调用模型**），耗时 **534ms**

**讲点三连**

1. 拒答发生在生成之前，所以又快又稳（534ms，而正常问答 2.5–3.9s，视问题而定）。
2. "检索到东西"不等于"有答案"——看 5 条来源的 score 量级就知道纯属近邻。
3. 边界诚实：语料是合成的，覆盖不到的问题明确说不知道，而不是用常识补。

## 5. 可选加分题

### 5.1 陷阱题（旧口径，讲"举一反三"用）

```text
采购金额300万以上的项目要提交什么会议审议？
```

实测（3.15s，7 条来源，未拒答）：模型**没有顺着 300 万回答**，而是先按现行细则分层（300–500 万→分管副总；500 万以上→总经理办公会），并指出旧《采购管理办法》第十二条已废止。

讲点：问题里带了误导数字，它反向纠正——这是"敢否定用户前提"。

### 5.2 库内有料题（证明覆盖得住）

```text
员工出差的住宿标准是多少？
```

实测（2.50s，6 条来源）：省会及计划单列市 500 元/天、其他地级市 400 元/天、县级及以下 300 元/天，并带出"2025-05-01 起试行两年"的时效信息。

## 6. 收尾话术（30 秒）

- **延迟**：主问题（500 万）同一问句多次实测 **2.7–3.9s**（`elapsed_ms` 2749 / 3302 / 3365 / 3827 / 3856）；其他问题 2.5–3.2s。TTFT p95 **3195ms**（2026-10-21 重跑；10-20 基线 4041ms），未达 1000ms 门禁。瓶颈是模型侧首 token 排队——**环境依赖，不是检索慢**，别承诺"3 秒内出答案"。
- **数据**：合成语料，结论不构成任何合规意见。
- **门禁**：INCOMPLETE（judge 失败率 **3.85%** > 2%；正确率 **68.00%**，facts 口径，2026-10-21 重跑）。如实讲，这正是教材要用的"失败史"。

## 7. 常见坑

| 现象 | 原因 / 处理 |
|---|---|
| 回车没发送 | Enter 发送，Shift+Enter 换行 |
| 发送按钮变灰 | 正在流式输出，等结束（正常 2.5–4s，慢时 5s+） |
| 徽标显示"未就绪" | 索引未加载或服务未起：`cd project\01-rag-qa; python -m src.server` |
| 答案显示"生成失败" | magpie 网关(3425) 没起或超时；检索与来源仍可用 |
| 右侧来源要滚很久 | 正常，8 条；点角标会自动滚到对应卡片 |
| 问了三四个问题才答 | 一次只问一个问题，问句越具体越稳 |

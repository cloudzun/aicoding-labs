# 实验手册编写体例（v1）

> **适用对象：** `L1-RAG问答实验手册.md`、`L2-NL2SQL实验手册.md`、`L3-合同审查实验手册.md`。
> **上位依据：** 内部文档 `HANDOFF-三案例教学化.md`（未随仓库分发）§5（体例与硬要求）、§2.5（环境前置）、§4.1（smoke 脚本与端点）。
> **一句话原则：** 手册是**给学生照着敲的**——每一步都要有"输入原文 + 期望输出 + 断言"，任何一步不能出现"你看情况"。

---

## 一、八段结构（顺序固定，段名固定）

| # | 段名 | 必须回答的问题 | 不写什么 |
|---|---|---|---|
| 1 | 实验目标 | 做完这个实验，学生**能做什么**、**多久**做完 | 不写课程意义、不写行业背景（那是教材的事） |
| 2 | 前置条件 | 环境装好了吗？服务起来了吗？网关通了吗？ | 不写安装原理 |
| 3 | 数据与基线 | 数据从哪来、规模多少、怎么确认和冻结快照一致 | 不写数据设计动机 |
| 4 | 操作步骤 | 每一步：**动作 + 输入原文 + 期望输出 + 断言** | 不解释"为什么这样设计" |
| 5 | 判据 | 通过长什么样；**失败长什么样** | 不写"差不多就行" |
| 6 | 常见错误 | 现象 → 原因 → 处理 | 不写"多试几次" |
| 7 | 提交物 | 交什么文件、放在哪、怎么命名 | 不写评分细则（教师用评分表） |
| 8 | 思考题 | 2–3 题，能回扣教材概念 | 不复述教材正文 |

## 二、各段写作规范

### 第 1 段：实验目标
- 一句话，动词开头，含**可验证结果**与**时长**。
- 正例：`90 分钟内，独立跑通政企制度问答，并验证"无答案问题会被拒答且不调用模型"。`
- 反例：`了解 RAG 的基本原理。`（不可验证）

### 第 2 段：前置条件
必含五个小项，缺一不可：

| 小项 | 写法 |
|---|---|
| Python 与依赖 | 给出**可复制**的 `pip install` 命令（含本项目特有依赖） |
| 模型网关 | `magpie` 在 `127.0.0.1:3425`；自检命令 `curl.exe -s http://127.0.0.1:3425/v1/models` |
| 端口 | 本项目端口（案例一 4180 / 案例二 4181 / 案例三 4182） |
| 工作目录 | `cd cases\0x-xxx`（**每步都从仓库根出发**，不要假设 cwd） |
| 断网影响 | 明确"无网关时哪一步必失败、哪些仍可跑" |

> **密钥纪律：** 手册正文**不得出现真实 key**。统一写 `<MAGPIE_KEY>`，并提示"向教师索取或使用本地 `.env`"。

### 第 3 段：数据与基线
- 三件事：**怎么生成**（命令）、**应该看到什么规模**（数字）、**怎么确认没跑偏**（校验值）。
- 必须给"不可变基准"：如果命令会重建数据，写明"重建后这些值必须不变"。

### 第 4 段：操作步骤（核心，占全篇 50% 以上）
每一步用**固定四元组**，缺一视为不合格：

```
### Lx-S<n> <动作一句话>
- 动作：<命令 / 接口调用 / 界面操作>
- 输入：<逐字原文（问句、请求体、点击的按钮名）>
- 期望输出：<真实跑出来的关键片段，可截断但必须逐字>
- 断言：<机器可判的条件，如「row_count == 1」「rejected.gate == "write_intent"」>
```

**四条硬要求：**
1. **期望输出必须实跑得到**，不许从别的文档抄（抄出来的往往已过期）。
2. 每 5 步以内必须有一次"可观察的成功信号"（避免学生敲 10 步才看到结果）。
3. 涉及 LLM 的步骤必须写"耗时量级"（如"约 2–5 秒，受网关排队影响"），否则学生会以为卡死。
4. **LLM 生成的文本每次会变**（SQL 写法、答案措辞、findings 顺序）——期望输出只约束**稳定字段**（如 `rows`、`row_count`、`rejected`、`summary`、规则号集合），并在该步注明"下列字段可变，勿逐字比对"。

**接口调用写法（推荐，可复制可断言）：**
```powershell
curl.exe -s -X POST http://127.0.0.1:4181/api/ask `
  -H "Content-Type: application/json" `
  -d '{"question":"2026年9月的应收合计是多少元？","clarify":true}'
```
> 中文请求体在 PowerShell 下易乱码：建议把 JSON 存成 UTF-8 无 BOM 文件，用 `--data-binary "@q1.json"`。

### 第 5 段：判据
必须成对写：

| 通过 | 失败 |
|---|---|
| `row_count == 1 且值 == 541252.34` | 值不等 → 数据未按 seed 重建，检查第 3 段 |
| `rejected.gate == "write_intent"` | 返回了 rows → 意图闸未生效，停止实验并报告 |

**禁止**只写"结果正确"这类无法判定的表述。

### 第 6 段：常见错误
表格三列：现象 / 原因 / 处理。至少 5 条，**优先收录学生真实会踩的**（端口占用、网关未起、编码乱码、旧数据未清、误把 `not_detected` 当合规）。

### 第 7 段：提交物
- 列清单 + 命名规则（如 `L2-<学号>-ex.json`）+ 存放路径。
- 至少一项是**机器可核对的产物**（评测 JSON / 报告 JSON），不能只交截图。

### 第 8 段：思考题
三档各 1 题：基础辨析（概念边界）/ 进阶分析（失败归因）/ 迁移研讨（换到自己业务怎么改）。
题目**必须能用手册里跑出的数据回答**，例如"你这次跑出的 JOIN 桶是多少？为什么它比单表桶低？"

## 四、正例：`L2-S3` 完整写法（来自真实接口）

```markdown
### L2-S3 问"2026年9月应收合计"，核对单值结果

- 动作：调用问数接口
  ```powershell
  curl.exe -s -X POST http://127.0.0.1:4181/api/ask `
    -H "Content-Type: application/json" `
    --data-binary "@q1.json"      # 内容：{"question":"2026年9月的应收合计是多少元？","clarify":true}
  ```
- 输入：`2026年9月的应收合计是多少元？`
- 期望输出（2026-10-21 实测，节选；`sql` 字段每次可能不同，已省略）：
  ```json
  {"columns":["amount_due"],"rows":[[541252.34]],"row_count":1,
   "attempts":1,"rejected":null,"chart":{"type":"kpi"}}
  ```
- 断言：`row_count == 1` 且 `abs(rows[0][0] - 541252.34) <= 0.01` 且 `rejected == null`
- **可变字段**：`sql`（模型写法每次不同）、`chart.reason`、`timings_ms`——**不要逐字比对**
- 耗时量级：约 2–5 秒（受网关排队影响；执行层仅 1–3ms）
```

**反例（不合格）**：`调用接口查询应收，应该能得到约 54 万。` —— 无端点、无请求体、无逐字期望值、无断言。

### 正例 2：`L3-S3`（含"可变字段"处理）

```markdown
### L3-S3 审查 CT003，确认命中两条缺陷

- 动作：调用审查接口
  ```powershell
  curl.exe -s -X POST http://127.0.0.1:4182/api/review `
    -H "Content-Type: application/json" `
    -d '{"contract_id":"CT003","with_semantic":false}'
  ```
- 期望输出（2026-10-21 实测，节选）：
  ```json
  {"summary":{"高":1,"中":1,"低":0,"必查缺失":1},
   "findings":[{"rule_id":"R19","level":"高","title":"赔偿上限比例"},
               {"rule_id":"R02","level":"中","title":"发票与税率条款"}]}
  ```
- 断言：`summary.高 == 1` 且 `summary.中 == 1`；`{"R19","R02"} ⊆ {findings[*].rule_id}`
- **可变字段**：`findings` 的顺序、`evidence` 引用的截断位置、`meta.elapsed_ms`
```

## 五、与教材的分工（重复即返工）

| 手册要写 | 教材要写 |
|---|---|
| 第几步敲什么命令 | 为什么这样设计 |
| 期望输出长什么样 | 这个输出的口径是什么、为什么可信 |
| 失败了怎么查 | 失败背后的机制与门禁原理 |
| 引用教材章节号（如"见单元5.3 §2"） | 引用手册步骤号（如"操作见 L2-S3"） |

## 七、篇幅与时长的经验值

| 项 | 建议 |
|---|---|
| 单本手册篇幅 | 250–400 行（与 90 分钟匹配） |
| 步骤数 | 8–14 步（含数据准备与评测） |
| 代码/命令块 | ≤15 行/块，长命令拆成"准备文件 + 一次调用" |
| 截图 | 每本 3–5 张（首页、关键结果、失败示范） |
| 已知答案数量 | 每本 ≥3 个"逐字可核对"的值（如 541252.34 / 57 / 35） |

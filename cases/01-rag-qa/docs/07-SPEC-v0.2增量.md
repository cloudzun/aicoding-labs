# SPEC v0.2 增量（评测口径重做 + claim 级引用）

> **性质：** 对 [SPEC v1](../SPEC.md) 的**增量修订**，不替换原文。凡本文未提及的条款，v1 继续有效。
> **触发：** 三轮评测数据显示 `partial` 占 53%，其中 14/40 的判词是"遗漏并列细节"——主干答对却判半对，说明**尺子本身有问题**。
> **纪律：** 口径变更必须**双报**（旧口径 + 新口径），且**禁止跨口径比较**。

---

## 一、变更清单

| 编号 | 条款 | 变更 | 理由 | 影响 |
|---|---|---|---|---|
| C-1 | AC-02 答案正确率 | 判定基准从"**整条条款全文**"改为"**最小事实点覆盖**"：每题标注 `facts[]`（1–4 条原子事实），全部覆盖=correct，部分=partial，全缺=wrong | 原口径要求覆盖条款每个并列细节（如"同步报送分管副总经理""报送内容与系统记录一致"），把主干正确的答案判成 partial | 正确率数值会变，需双报 |
| C-2 | 冲突/时效 8 条 | **改人工判定**：由人给出 `verdict ∈ {correct, partial, wrong}` 与理由，机器 judge 结果仅作参考 | judge 用"是否覆盖标准答案"衡量不了"指出冲突并请确认"这一正确行为 | 8 条的判定人从模型变为人（判定人：Lead，客户抽检 20%） |
| C-3 | 新增 AC-11 | **claim 支撑率 ≥90%**：答案按句切分，每个带 `[cNN]` 的句子与所引 chunk 做字符 3-gram Jaccard，阈值 0.15；低于阈值记 `unsupported_claim` | 现有"引用可定位率"只证明编号存在（评审 F05），不证明引用支撑论断 | 新增指标，报告增加一列 |
| C-4 | 新增 AC-12 | **judge 失败率 ≤2%**：失败率高时整体结论标 `INCOMPLETE`，不得给 PASS/FAIL | 实测曾出现 42.5% 判定失败，导致正确率不可读 | 评测可信度门禁 |
| C-5 | 报告格式 | 必须同时给出"旧口径 / 新口径"两列，并注明**不可跨口径比较** | 防止口径变更被误读为"调门禁" | 报告模板变更 |

**不变项（明确声明）：** AC-01 召回口径、AC-04/05 拒答口径、AC-06 引用可定位口径、AC-07/08 延迟口径与阈值**全部不变**；延迟仍是未达标项，不因本次改口径而改变。

## 二、新增数据契约

### 2.1 golden_set_v2（在 v1 基础上加字段）

```json
{
  "qid": "a-001",
  "split": "single_hop",
  "question": "...",
  "gold_chunk_ids": ["zdcg-2023-001#c012"],
  "gold_answer": "（条款全文，保留）",
  "facts": ["300万元以上提交总经理办公会审议", "100万至300万由分管副总经理审批"],
  "facts_source": "llm_extracted",
  "source": "llm_generated",
  "answerable": true
}
```

`facts` 生成规则（`scripts/make_gold_facts.py`）：
1. 从 `gold_answer` 抽取 1–4 条**可独立判定的原子事实**（含数字、主体、动作三要素）。
2. 数字/期限类必须逐条单独成 fact（不允许合并成"审批权限见第十二条"）。
3. 抽取后人工抽检 20%（本轮抽检人：Lead）。

### 2.2 human_verdicts.jsonl（冲突题人工判定）

```json
{"qid":"h-01","verdict":"correct","reason":"答案给出500万现行口径，并说明2023办法第十二条已被2025细则第二十六条废止","judge_by":"lead","judge_at":"2026-10-20"}
```

### 2.3 回答契约新增字段（SSE `done` 与 trace）

| 字段 | 含义 |
|---|---|
| `unsupported_claims` | 支撑度低于阈值的句子列表（含句子、引用编号、重叠度） |
| `claim_support_rate` | 1 − unsupported / 带引用句子总数 |
| `judge_error`（仅在评测产物中） | judge 调用失败标记，不计入分母 |

## 四、无偏检索评估（补充 AC-01）

**问题：** 现有 208 条评测题的 gold 就是出题所依据的 chunk，Recall@5=100% 不能代表真实提问。

**方案：** 新增 `eval/human_questions.jsonl`——**20 条人工撰写**的问题，只标注"期望命中的文档（doc_id）与条款号"，不参与出题流程。

- 指标：`Doc-Recall@5`（期望文档出现在 top-5 结果中的比例）与 `Clause-Hit@5`（期望条款号出现）。
- 用途：①作为 AC-01 的无偏补充；②作为 C 段嵌入模型 A/B 的比较基准。
- 局限：20 条只能给趋势（CI 约 ±19pp），结论只作方向判断，不作验收依据。

## 五、本次不做的

- 不改召回/拒答/延迟阈值（避免"为结果让路"）。
- 不做多轮评测集（仍只演示）。
- 不引入新的外部评测框架（RAGAS 等）：当前自研评测已能覆盖，引入会带来一致性成本。若后续要对接，另立 SPEC。

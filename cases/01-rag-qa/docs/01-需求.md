# 环 1 · 需求（RAG 项目）

> **说明：** 标准 `/office-hours` 是用 YC 式逼问把模糊需求问清。本项目需求已由客户的验收表给定，因此本环采用**压缩版 office-hours**：只补齐三件客户没给的东西——**用户是谁、成功是什么样、明确不做什么**。
> **上游：** [环 0 数据与口径](00-数据与口径.md)（已关闭）
> **下游：** 环 2 SPEC（验收标准逐条对应环 0 的六项指标）

---

## 1. 一句话定位

**一个能回答"我们公司制度怎么规定的"并指回原文段落的问答助手**，面向政企/运营商内部的制度检索场景；回答不出来时明确说"资料不足"，不编造。

## 2. 用户与场景

| 角色 | 典型问题 | 现在的作法 | 期望改善 |
|---|---|---|---|
| **普通员工** | "出差住宿标准是多少？""合同超过 500 万谁审批？" | 翻 OA 制度目录 → 下载 PDF → Ctrl+F；常常翻错版本 | 一次问答 + 引用定位，30 秒内拿到答案与依据 |
| **新入职员工** | "报销流程一共几步？找谁签字？" | 问同事/查手册 | 能连续追问（多轮），逐步澄清 |
| **制度管理员** | "这份旧规定还有效吗？和新的冲突吗？" | 靠记忆与经验 | 系统主动指出新旧冲突与生效日期 |
| **审计/合规** | "这条答复依据哪一条？" | 无法追溯 | 引用可点开原文段落 |

**关键洞察：** 这个场景的价值不在"答得快"，而在**"敢照着做"**——所以引用可定位与拒答，比流畅度重要得多。

## 3. 用户故事（每条带验收点）

| # | 故事 | 验收点 |
|---|---|---|
| U1 | 作为员工，我问一个单一条款能回答的问题（如审批额度），能在 3 秒内看到首字，并被准确引用到条款 | 准确率分桶：单跳 ≥90%；引用可定位 |
| U2 | 作为员工，我问一个需要跨两份文件的问题，系统能给出综合答案并分别标注来源 | 多跳分桶如实报数（不承诺 85%） |
| U3 | 作为员工，我问一个知识库没有的问题，系统明确说"资料不足，建议咨询 XX 部门"，不编造 | 应拒答率 ≥90%，编造率 ≤10% |
| U4 | 作为员工，我先问"采购审批额度"，再问"那它需要几个人签字"，系统能理解"它" | 多轮演示通过（不纳入指标验收） |
| U5 | 作为员工，我点答案里的引用，能跳到原文所在段并高亮 | 引用可定位率 ≥95% |
| U6 | 作为制度管理员，我提出一个新旧版本规定不同的情形，系统指出冲突并给出两版生效日期 | 冲突类 20 题行为正确率 |
| U7 | 作为审计，我要求看某次回答用了哪些 chunk、耗时多少 | 每次回答留存 trace（chunk id + 耗时 + 模型版本） |

## 4. 范围（做什么）

1. **文档入库**：PDF/Word/Markdown 解析 → 结构化切分 → 保留 `doc_id/page/block/条款号` 元数据 → 向量 + 关键词双索引。
2. **混合检索**：dense（bge-m3）+ sparse（BM25，jieba 分词）+ 融合 + rerank（bge-reranker-v2-m3）。
3. **生成与溯源**：答案 + 强制引用标注 `[doc_id#chunk]`，前端可点击定位。
4. **多轮**：会话上下文 + 指代消解（"它/这个规定/上面那个"）。
5. **拒答**：检索分数低于阈值或上下文不支持时，明确拒答并给转人工建议。
6. **评测**：一条命令跑 250 条评测集，出 Markdown + JSON 报告（六项指标 + 分桶 + 错误分类）。
7. **管理端（极简）**：上传文档、查看索引状态、触发重建、查看单次问答 trace。

## 5. 明确不做（"NOT in scope"，写死防止蔓延）

- ❌ 权限体系与多租户（只留接口位）
- ❌ 扫描件 OCR
- ❌ 文档版本管理与审批流
- ❌ 模型微调/继续预训练
- ❌ 完全离线私有化部署（当前环境不具备，见 `ENVIRONMENT.md`）
- ❌ 移动端适配（只做桌面 Web）
- ❌ 多轮纳入验收指标（只做演示）

## 6. 关键决策（已定 / 待定）

| 决策 | 结论 | 依据 |
|---|---|---|
| 生成模型 | `opencode-go/gpt-6-luna` + `reasoning_effort=none`（备用 deepseek-v4.1-flash） | 实测 p50 1.48s、稳定；glm 抖动到 18s |
| 嵌入/重排 | 硅基流动 bge-m3 / bge-reranker-v2-m3 | magpie 无嵌入模型 |
| 向量存储 | numpy 内存索引 + 磁盘持久化（千级 chunk） | Windows 本机、零服务依赖、教学可读 |
| 语料 | 公开政策文件 + 合成制度库 | 用户 2026-10-20 拍板 |
| 前端 | 极简静态页 + FastAPI（无需构建工具） | 降低课堂环境风险 |
| 延迟口径 | TTFT p95 + 流式完成 p95 | 环 0 结论 |

## 7. 成功标准

**运营性（客户视角）**
- 员工能在一个对话框里 30 秒内拿到"能照着做"的答案与依据。
- 制度管理员能当场看到"新旧规定冲突"被系统指出。

**工程性（我们视角）**
- 六项指标达到环 0 阈值，且报告可复现（一条命令）。
- 每次回答可回溯到 chunk、模型版本、耗时。
- 演示可在断网降级模式下不崩（嵌入不可用时明确报错而非静默胡说）。

## 8. 风险 Top 3

| 风险 | 影响 | 对策 |
|---|---|---|
| 解析质量差导致召回无法达标 | 指标全面不达标 | 只用文本型 PDF；解析后人工抽检 20 页；必要时改结构化切分策略 |
| 模型延迟抖动（实测 p50 1.5s → 18s） | 演示超时 | 流式 + 8s 熔断 + 备用模型；延迟以 p95 口径承诺 |
| 合成语料的"假"被客户质疑 | 演示说服力下降 | 首页明确"示例数据"，并以公开真实文件做主体；合成部分只承担难例 |

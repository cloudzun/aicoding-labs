## 2. 为什么裁剪

- 时间：③ 整体时间盒 5 天，把环 3 压缩为"SPEC 内嵌评审清单 + 事后独立评审"。
- 当时的理由：合成合同、规则由我方拟定，判断"不需要法务"。
- **这个理由后来被证伪**（见 §4）。

## 3. 替代做法

1. `SPEC.md` 里写入 11 条 AC + 四类契约 + 风险对策，作为自审清单；
2. 施工后用 **codex 独立评审**（26 条：3 Critical / 17 High / 6 Medium），讨论见 `review-codex.md`；
3. 对评审出的问题做"修 / 部分修 / 登记未修"三分类。

## 4. 裁剪的代价（用数据说话）

**语义型精确率只有 51.79%，其中 27 个误报里有 20 个来自同一条规则 R23（管辖地）。**

| 现象 | 数据 | 根因 |
|---|---|---|
| 正常合同被判"管辖不利" | 20/27 误报 = R23，证据全是"提交甲方所在地人民法院诉讼解决" | **规则没有声明"站在甲方立场"**；模型按中立/乙方视角判，认为对乙方不利 |

**如果当时做了法务会审，这五个问题一定会被提出：**

1. 这份合同是替**谁**审？（甲方 / 乙方 / 中立第三方）——**这一条缺失直接导致 20 个误报**
2. 风险等级的映射谁定？（违约金偏低是"中"还是"高"）
3. 缺失项与不利条款，哪个优先级更高？
4. "视为风险"的边界：格式瑕疵算不算？
5. 报告给谁看，能不能作为拒签依据？

**结论：环 3 裁掉的不是"流程"，而是"立场定义"。** 这是后续 R3-10 的由来。

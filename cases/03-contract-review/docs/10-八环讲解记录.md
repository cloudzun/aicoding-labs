# 合同审查 demo 八环讲解记录

> **用途**：课堂讲解用（与 ①② 同体例，本份为压缩版）。复现见 [11-操作手册](11-操作手册.md)。
> **读法**：每环四件事（输入 / 分析 / 决策与依据 / 门禁与产出）+ 一句要点。
> **与 ①② 的最大差别**：①② 的正确答案能算出来；③ 的"风险"是**主观判断**。所以 ③ 的流程重点是**把主观拆成"可确定性判的"与"必须靠模型的"两部分，并给后者装上证据约束**。

---

## 零、起点：客户给了一张指标表

> 核心风险识别召回 ≥88%、10 页合同 ≤10s、风险分级、结构化报告。

**这四条里有三个必须先回答的问题**：召回的分母是"合同"还是"条款单元"？"风险"按谁的立场判？"分级"的映射规则谁定？
——这三个问题决定了 ③ 必须先做环 0，而不能先写代码。

## 二、环 0：先定"判定单元"和"谁说了算"

### 输入
客户验收表。

### 分析
- **判定单元 = 规则 × 合同 = 810**。若按 30 份合同计，95% 置信区间 ±14pp——评测等于没做。
- **真值来源**：植入式（生成器按计划写缺陷，真值同时产出），不做事后人工标注（810 单元人力不可行）。
- **立场问题**：同一句"提交甲方所在地法院"，对甲方有利、对乙方不利。**必须先定"站谁的角度"**（本轮定为甲方视角，未落实为规则字段 → 成为 R3-10 债务）。

### 决策与依据
| 决策 | 依据 |
|---|---|
| 30 份 / 3 类 / 24 缺陷 + 6 正常 | 有正常样本，精确率才有意义 |
| 规则 27 条 YAML | 可机读、可版本化、可替换客户清单 |
| 缺陷池覆盖每条规则 | 首轮断言拦下 9 条"从未被违反"的规则 |

### 门禁与产出
数据 10/10 断言（合同数/单元数/正常零风险/植入数=真值数/每条规则至少违反一次）。

### 讲解要点
**"'召回 88%'这句话里，分母、立场、分级映射三个都没定义——不定义就没法验收。"**

---

## 三、环 1/2：双引擎与报告契约

### 分析
把 27 条规则按"能不能确定性判"分两堆：

| 堆 | 规则 | 判法 | 依据 |
|---|---|---|---|
| 确定性 | 21 条 | 标题匹配 / 正则 / 阈值 / 结构校验 | 单份 ~7ms，可测 |
| 语义 | 6 条 | LLM + **证据必须可定位 + 属于该规则主题** | 无证据则降级 `not_detected` |

### 决策与依据
| 决策 | Rejected | 依据 |
|---|---|---|
| LLM 不得新增规则 | 让模型自由发挥 | 规则清单是验收依据 |
| `not_detected` 显式列出 | 默认视为合规 | "没看出" ≠ "没问题" |
| v1 只支持 docx | 支持 PDF | 解析质量会污染全部指标 |
| 页号为估算并标注 | 假装精确 | python-docx 无分页信息 |

### 讲解要点
**"把主观判断装进'必须有证据'的笼子里，是 ③ 唯一能站住的工程解法。"**

---

## 四、环 4/5：数据生成器才是最大的偏差源

### 分析
本轮最贵的 bug 全部出在**生成器**，不是检测算法：

| 缺陷 | 现象 | 修法 |
|---|---|---|
| 未植入也写缺陷版 | 每份合同自带无限责任 → 语义误报 39 条 | 区分正常版/缺陷版文本 |
| 语义文本占用别的标题 | "缺违约责任"永远测不出（recall 0%） | 标题去冲突 |
| 缺陷互斥冲突 | 真值自相矛盾（缺 R11 同时又有违约条款） | 生成器冲突消解 |
| 关键词满篇匹配 | "期限"命中"保密期限"，缺失型 recall 25% | 改条款标题匹配 |

**修完这四条，存在型从 86.67% → 100%，语义误报从 39 → 27（再经 JSON 修复降到精确率 50%）。**

### 讲解要点
**"AI 项目里，数据生成器的默认分支往往就是最大的偏差来源——它一次污染 30 份合同、810 个单元。"**

## 五、环 6/7/8：功能全绿，指标一半

| 项 | 结果 |
|---|---|
| QA | 10/10（含注入防御） |
| 存在型 P/R/F1 | **100/100/100** |
| 数值型 / 结构型 Recall | **100% / 100%** |
| 缺失型 Recall | **100%**（v1.1 前 84.21%） |
| 语义型 Recall | **87.10%**（修 JSON 之后） |
| 语义型 Precision | ≈50%（**未入门禁**） |
| 等级/定位/报告结构 | 100% / 100% / 100% |
| 锚点一致率 | 85% |

**复盘的三个新教训：**
1. "判不准"与"没解析出来"要分开——语义召回 16% 其实是 JSON 截断（① 的 judge 截断第三次重演）。
2. 主题守卫是精确率/召回的硬取舍，选择了"宁可说没看出来"。
3. **评审期间数据必须冻结**：codex 因为发现 `CT005.docx` 在被改写而拒绝出结论——这是它这一轮最有价值的输出。

### 讲解要点
**"功能全绿不等于指标过半；而指标不达标里，至少一半责任在数据与测量，不在模型。"**

## 七、一页话总结

**① 教"敢不敢说不知道"，② 教"对错能不能被机器判定"，③ 教"主观判断怎么被工程约束"。**

③ 的答案是两条：**能确定性判的绝不交模型**（21 条，满分），**必须交模型的必须带证据**（6 条，召回 87%、精确率 50%）。剩下的一半短板不在算法，而在"规则的立场没定义"和"语义评审没有自检集"——这两条都已写进债务与下一轮 P0。

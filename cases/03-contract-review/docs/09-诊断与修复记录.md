# 诊断与修复记录（v1.0 → v1.1）

> **为什么单列一章：** 这是三个案例里第一次"**指标不达标 → 先诊断 → 只改一处 → 全部转绿**"的完整闭环，适合课堂逐段讲。
> 与 ① 的 `docs/09-三阶段结果.md` 对应：①是变量隔离的三段攻坚；③是一次**根因诊断**。

---

## 0. 起点

| 指标 | v1.0 实测 | 门槛 | 差距 |
|---|---|---|---|
| 缺失型 Recall | 76.67%（23/30） | ≥85% | −8.33pp |
| 定位率 | 47.62%（确定性）/ 64.13%（含语义） | ≥90% | −42pp |
| 语义精确率 | 51.79% | 未设门禁 | 无门槛 |

用户提问："这两个指标还有提升空间吗？先判断，别动手。"

---

## 1. 诊断（只读脚本，不改逻辑）

**脚本：** `scripts/diag_metrics.py`；证据：`evidence/diag-deterministic.json`、`diag-semantic-subset.json`。

### 1.1 缺失型 7 条 FN 的逐条打印

结果高度集中：**7/7 全是 R11（违约责任）**，且这 7 份合同的标题列表里**都没有"违约责任"**，但报告判"存在"。原因：

```
'第二十条 对等责任　双方违约责任对等，逾期均按合同总额的 0.5‰/日计违约金。'
                                    ↑ 正文里的"违约责任"被当成标题命中
```

判定条件是「段落含标题词 **且**（长度≤60 **或** 以"第X条"开头）」，这段以"第二十条"开头 → 通过。

### 1.2 定位可用性分解

| 类别 | 有真实 locator | 无 locator |
|---|---|---|
| 数值型 | **26 / 26** | 0 |
| 结构性 | **4 / 4** | 0 |
| 语义型（子集 6 份） | **13 / 13** | 0 |
| 存在型（判"条款缺失"） | 0 | 33 |
| 缺失型 | 0 | 23 |

**结论：可定位项定位率 = 100%。** 47.62% 的分母里混入了 56 条"没有位置可指"的缺失项。

## 2. 修复（三处，无一处涉及模型）

| 改动 | 代码 | 说明 |
|---|---|---|
| 标题匹配限定范围 | `engine.heading_part()` | 只取"第X条"后到换行/前 24 字 |
| 标题别名机制 | `rules.yaml: heading_aliases` | R11 责任承担/违约处理、R12 成果权属、R09 有效期（真实合同预留，合成语料未触发） |
| 缺失项位置推断 | `engine.infer_missing_locator()` | 给参照段落并标 `inferred=true` |
| 指标拆分 | `eval/run_eval.py` | 定位准确率（可定位项）+ 缺失项位置覆盖率（推断）+ 旧口径对照 |

## 3. 结果

| 指标 | v1.0 | v1.1 | 性质 |
|---|---|---|---|
| 缺失型 Recall | 76.67% | **100%（30/30）** | 真能力提升（一处 bug） |
| 缺失型误报率 | 0% | **0%** | 未牺牲精确率 |
| 存在型 P/R/F1 | 100/100/100 | **100/100/100** | 无回归 |
| 定位准确率（可定位项，n=30） | 未定义 | **100%** | **度量修正**（旧 47.62% 分母含无位置项） |
| 缺失项位置覆盖率（n=63，推断） | 未定义 | **100%** | 新能力，但位置是推断 |
| 锚点一致率 | 85% | **100%** | 同一 bug 的连带效果 |
| 语义精确率 | 51.79% | **100%**（v1.2 加立场字段后） | 见 §6 |

**门禁**：从 2 项 FAIL → **10/10 PASS**。

---

## 4. 这一轮最该讲的三句话

1. **"指标低"不等于"能力差"，也不等于"要大改造"。** 我最初给用户的方案是"模板域先验 + 条号连续性，约半天"；诊断后发现真因是一处匹配范围，改 3 行。
2. **换分母不算提升。** 定位率 47.62% → 100% 是**口径变化**，旧口径只能作对照，不许写成"定位能力提升 52pp"（已写进 DECISIONS C-20）。
3. **连带效果要看清楚。** 锚点 85% → 100% 不是另外修的，是同一个 bug 修复带来的——说明锚点当初就抓到了模式，只是我们把原因归错了。

## 5. 还没解决的（同一轮发现，未修）

| 编号 | 问题 | 量化影响 |

| **R3-10** | 规则未声明立场 | **20/27 语义误报来自 R23**（"提交甲方所在地法院"被判风险）；加立场预计精确率 51.79% → 约 80% |

> R3-10 的根因不在代码，而在**环 3 少了法务会审**（见 `03-会审记录.md` §4）——这是三个案例里"流程裁剪直接变成指标缺陷"的最清晰例证。

## 6. v1.2 后续：立场字段把精确率做到 100%

| 项 | 内容 |
|---|---|
| 改动 | `rules.yaml` 增 `stance: 甲方（采购方）` + `stance_note`；R23/R25 增 `stance_hint`；语义 prompt 注入立场 |
| 效果 | 语义精确率 51.79% → **100%**（FP 27 → 0）；召回 93.55% → 90.32%（少 1 条 TP） |
| 代价判断 | 可接受：少一条真风险 < 20 条假风险 |
| 门禁 | v1.2 起语义精确率 ≥70% 入门的（**新增约束，历史 PASS 不含**） |

**这条值得单独讲：** 20/27 的误报不是模型判错，而是**没人告诉它替谁审**。参数一行、字段一个，收益 48pp。

# 环 1 · 需求（NL2SQL）

> 压缩版 office-hours（需求由客户验收表给定）：只补"用户、成功、不做"三件事。
> 上游：[环 0 数据与口径](00-数据与口径.md)

## 1. 一句话定位

**一个能用中文问政企业务数据、自动出 SQL 与结果、并把口径讲清楚的数据问答助手**；答不了的（口径歧义、越权、写操作）必须明确拒绝或反问。

## 2. 用户与场景

| 角色 | 典型问题 | 现在怎么干 | 期望 |
|---|---|---|---|
| 政企客户经理 | "杭州的制造行业客户这个月营收多少？" | 提需求给数据组，等 1–3 天 | 30 秒内拿到数字 + 看得到 SQL |
| 地市分公司管理 | "本季度 SLA 超时的工单集中在哪个班组？" | Excel 手工透视 | 一句话出分组统计 + 图表 |
| 网络运维 | "近三月故障工单平均响应时长？" | 导出明细再算 | 直接给结果，说明是否排除未响应 |
| 审计/数据治理 | "这份报表的营收口径含不含调整？" | 问人 | 语义层直接给出口径定义 |

**关键洞察：** 这个场景的价值不是"替代 BI"，而是**"让口径可解释"**——SQL 可见、口径可查、歧义要反问。

## 3. 用户故事（带验收点）

| # | 故事 | 验收点 |
|---|---|---|
| U1 | 我问单表筛选类问题，能直接得到结果 | 单表桶 EX ≥90% |
| U2 | 我问跨两/三张表的问题，SQL 关联正确 | JOIN 桶 EX ≥80% |
| U3 | 我问分组排名问题，能出正确 Top N 与图表 | 聚合桶 EX ≥85%；图表类型合理 |
| U4 | 我问含"近三月"的问题，口径与语义层一致 | 时间窗口桶 EX ≥80% |
| U5 | 我问含"没响应过的工单"这类空值/否定问题，结果正确 | 否定空值桶 EX ≥80% |
| U6 | 我问"营收多少"，系统指出口径歧义（含不含调整） | 歧义集反问率 ≥60% |
| U7 | 我尝试让它删数据/查系统表，被拒绝且给出原因 | 安全闸 4/4 生效 |
| U8 | 我要求看某个结果的 SQL 与用到的口径 | 界面可见 SQL + 口径清单 |

## 4. 范围

**做：** 中文问句 → SQL → 校验 → 执行 → 结果表 + 图表建议 + SQL 与口径展示 + trace；四道安全闸；EX 自动评测；歧义反问。

**不做：** 多轮追问（仅演示）、写操作、跨库、模型微调、完全离线、复杂 SQL（窗口函数的高级用法不承诺）。

## 5. 关键决策（已定）

| 决策 | 结论 | 依据 |
|---|---|---|
| 是否用 schema 检索 | **不用**，全量 schema + 语义层入 prompt | 6 张表 ~1.5k token，全量更可靠 |
| 判定方式 | **EX 全自动**，零 judge | 与 RAG 最大差异：正确答案可执行 |
| 纠错 | ≤2 次重试，每次重新过安全闸 | 防无限重试 + 防绕过 |
| 图表 | 规则表（数据形态 → 图表类型），不交给模型 | 可解释、可测试 |
| 前端 | 静态单页，SQL 可见 | 无构建链 |

## 6. 成功标准

**业务侧：** 客户经理能自己问出数字并看到依据；审计能查到口径。
**工程侧：** EX ≥85%；可执行率 ≥95%；四道闸 100% 生效；每次请求留 trace；改 prompt/语义层后能一条命令重跑对比。

## 7. 风险 Top 3

| 风险 | 对策 |
|---|---|
| 模型不懂口径 → 答错但看起来对 | 语义层入 prompt + EX 分桶看"时间/歧义"两桶是否显著低 |
| JOIN 放大行数（产品同名、重复客户） | 语义层明确"按 ID 关联"；专项题覆盖 |
| 生成 SQL 破坏数据 | 只读连接 + authorizer 双保险（即使提示词被绕过也写不进去） |

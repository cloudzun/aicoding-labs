# 迭代记录（NL2SQL）：EX 80.67% → 84.67%

> 本章补记 ② 的"指标修正闭环"。原始数据：`evidence/eval-main-20261020-131926.json`（修正前）、`eval-main-20261020-143545.json`（修正后）。
> 与 ① 的 `docs/09-三阶段结果.md`、③ 的 `docs/09-诊断与修复记录.md` 同属"迭代专章"。

---

## 1. 起点

主集 150 题 EX = **80.67%（121/150）**，可执行率 100%，锚点 100%。
缺口 4.33pp，但**分桶差异极大**：单表 87.5%、两表 56.7%、三表 70%、聚合 93.3%。

## 2. 一次独立评审带来的修正

codex 评审 19 条中，**5 条直接指向"评测器失真"**（不是模型能力）：

| # | 缺陷 | 影响 |
|---|---|---|
| 1 | 评测拿 pipeline 的**展示结果（截 200 行）**与完整 gold 比 | gold>200 行的题正确也必错（si-014 498 行、si-027 315 行） |
| 2 | 无序比较用字符串键、绕过 `cell_eq`，并按位置绑列 | 季度标签 `2026Q1` vs `2026-Q1`、列序不同 → 假失败 |
| 3 | 7 道标量题 gold 多带常量维度列 | 正确答案返回单值 → 判列数不同 |
| 4 | gold 按 `customer_name` 聚合 | 同名客户 `C0002` 与 `C0002-DUP` 被合并 |
| 5 | gold 用 `sla_flag='Y'`，语义层却是"4 小时时长口径" | gold 与口径自相矛盾 |

## 3. 修复与结果

| 修复 | 做法 |
|---|---|
| 展示截断 | pipeline 增加 `rows_full`，评测用全量；界面仍截 200 行 |
| 比较器 | 统一走 `cell_eq`（容差 + 标签归一化 + NULL 类型优先），按行多重集比较 |
| gold 修正 | 去维度列、按 `customer_id` 分组、SLA 改时长口径 |
| 退出码 | PASS→0 / FAIL→2 / INCOMPLETE→3；`--limit` 仅冒烟 |
| 延迟 | 纳入门禁 |

**结果：**

| 指标 | 修正前 | 修正后 |
|---|---|---|
| EX | 80.67% | **84.67%（127/150）** |
| 单表桶 | 87.5% | **97.5%** |
| 两表桶 | 56.7% | **63.3%** |
| JOIN 桶（两表+三表） | 62.0% | **68.0%** |
| 可执行率 | 100% | 100% |
| 锚点 | 100% | 100% |

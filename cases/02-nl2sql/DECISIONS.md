## 二、判定与评测

| 编号 | 决策 | Rejected | 依据 | 证据 |
|---|---|---|---|---|
| N-06 | **EX 全自动判定，零 judge 依赖** | LLM judge | 正确答案可由 SQL 执行得到，不需要主观判定；同时绕开 ① 的 judge 不稳定坑 | `eval/run_eval.py` |
| N-07 | 先写 gold SQL 并执行，再让 LLM 反写问题 | 先写问题再写 SQL | 避免"问题与标准答案错位"；结果集是执行出来的，骗不了人 | `scripts/build_gold.py`、`gen_questions.py` |
| N-08 | 有 LIMIT 必须配 ORDER BY（否则去掉 LIMIT） | 允许无排序 LIMIT | 无排序时"前 N 条"不可判定，模型自行加序即判错，属不公平 | `scripts/patch_limit_invariant.py` |
| N-09 | 行顺序只在**题面明确要求排序**时校验 | 只要 gold 有 ORDER BY 就校验 | 模板 ORDER BY 是出题脚手架，不是题面要求 | `patch_round2b.py`、tw-002 由 FAIL 转 PASS |
| N-10 | 锚点集 20 条人工题（与生成流程隔离） | 只用生成题 | 生成题与 SQL 同源，会高估；锚点用于校准 | `eval/anchor_set.jsonl` |
| N-11 | 题面必须覆盖 SQL 全部输出列 | 允许模型少输出列 | 否则"合理地只答被问的列"会被判错（si-005 三列 vs 两列） | `gen_questions.py` 提示词 |
